# Methodology

The live check used Codex CLI 0.172.0 and calculator baseline `39f772e`. It installed the proxy adapter into an isolated Codex home, used an existing ChatGPT-backed login, ran a fixed one-turn prompt in an empty read-only workspace and queried the session and successive checkpoints. A second experiment resumed an isolated session for one additional turn and compared both checkpoint increments with the cumulative rollout. Raw rollout records were projected onto an allowlist of model and token counters. Fixtures omit timestamps, paths, thread IDs, rate-limit state, credentials and interaction content. The maintainer script still performs its original working-tree CSV comparison, while the independent audit reads these allowlisted rollout records and a separately transcribed official rate snapshot.

For the fresh single-model fixture, the reference accepts an increment only when it equals the difference between the current and previous totals. Consecutive equal totals contribute zero. The fixture reader rejects gaps and model switches because a single rolling snapshot cannot recover runtime model attribution or shared history. This rule is scoped to the fixture shape.

Production observations and local rollouts are distinct evidence channels. The offline HTTP replay reconstructs a Responses terminal payload from the fixture and checks that the proxy records the same tokens and cost. The live run uses the real upstream. Additional differential tests feed deterministic generated records through the production record path and compare exact per-call amounts before formatting. Aggregates compare at their eight-decimal display precision. A restart test runs the same split usage through both durable backends.

An official reconciliation would also require an authorized Platform API project and organization admin key. Keep the project isolated, capture UTC windows and request identifiers separately, allow reporting to settle, and inspect line items and currency. The opt-in script compares daily project costs, including any non-token charges, with an operator-supplied expectation. A daily match only supports the experiment when the project has exclusive usage and the expectation covers every line item. ChatGPT allowance or credit consumption requires separate evidence from the subscription.
